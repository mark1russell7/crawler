[Part A](../tokens-per-claim/) of the eval counted the tokens that an agent reads to prove {count} claims with exact quotes. It used a proxy tokenizer and no model. Part B asks the same questions in real sessions of Claude Code (`claude -p`), in CI. The tokens and the cost come from the usage that Claude Code reports, with each model of the session.

Each claim got one session in each of two arms, with the same prompt and the same model:

- **`mcp`**: only the MCP tools of polite-crawler-mcp, with a new store.
- **`webfetch`**: only the built-in tool WebFetch.

The results:

- **In real sessions, WebFetch costs approximately half as much as polite-crawler.** With Sonnet, the median session costs {usd(S.webfetch.medianCostUsd)} with WebFetch and {usd(S.mcp.medianCostUsd)} with polite-crawler. With Opus, it costs {usd(O.webfetch.medianCostUsd)} against {usd(O.mcp.medianCostUsd)}.
- **The token saving of part A does not give a lower cost.** WebFetch gives the page to a small, cheap model (<code>{evalB.helper}</code>). The main model reads only the answer of that small model.
- **With Sonnet, polite-crawler gives more quotes that are word for word on the page:** {S.mcp.onPage} of {S.mcp.sessions} against {S.webfetch.onPage} of {S.webfetch.sessions}. With Opus, the two arms are almost equal: {O.mcp.onPage} of {O.mcp.sessions} against {O.webfetch.onPage} of {O.webfetch.sessions}.
- **Only polite-crawler lets the agent check its quote.** `crawl_verify` finds the quote in the stored page, and the stored capture has an id that a citation can name. With WebFetch, the main model does not see the page, so it cannot check the quote.
- **The whole eval cost {usd(evalB.costUsd)}** for {allSessions} sessions, with a dry run of {evalB.dryRun.sessions} sessions.

### Two checks of an answer

- **The quote of the claim** (`verified`): the answer holds the quote of the claim.
- **Quotes on the page**: each quote of the answer is on the page, word for word.

The two checks give different counts. An answer can quote a different sentence of the page. Then its quote is on the page, but it is not the quote of the claim. For the question "What does the map method of an array return?", the two arms quoted "A new array with each element being the result of the callback function." That sentence is on the page and answers the question, but the claim has a different sentence. By the check of the claim, WebFetch has a few more: {S.webfetch.verified} against {S.mcp.verified} with Sonnet, and {O.webfetch.verified} against {O.mcp.verified} with Opus.

With Sonnet, most quotes of WebFetch that are not on the page join or drop text. Examples are a footnote mark "[1]" in the quote, the pronunciation left out of "Alan Mathison Turing (23 June 1912 – 7 June 1954)", and two sentences joined as one. The small model of WebFetch reads the page, and the main model gets only its answer.

The misses of polite-crawler are all on one claim: the status code 418 of RFC 9110. That quote is past the cut of the reader, at 50,000 characters. One session gave a quote that is not on the page. Two sessions, one with each model, stopped at the limit of turns with no answer.

## The cost of a session

Part A counted fewer tokens for polite-crawler. Why does WebFetch cost less? The two arms read their tokens with different models.

- **polite-crawler:** the main model reads each token. Each session starts with the system prompt of Claude Code, the definitions of the nine tools and the instructions of the server. The median session has {S.mcp.medianTurns} turns, and each turn reads the context again from the cache. With Sonnet, the median session reads {tokens(S.mcp.medianReadTokens)} tokens.
- **WebFetch:** the small model reads the page, and the main model reads only its answer. The median session has {S.webfetch.medianTurns} turns and reads {tokens(S.webfetch.medianReadTokens)} tokens with the two models. A token of the small model costs much less than a token of Sonnet.

With Sonnet, the WebFetch arm cost {usd(S.webfetch.costUsd)} in total: {usd(S.webfetch.mainUsd)} for Sonnet and {usd(S.webfetch.helperUsd)} for the small model. The polite-crawler arm cost {usd(S.mcp.costUsd)}, all for Sonnet.

The fixed part of the cost is large. With Sonnet, the cheapest session cost {usd(cheapest(sonnet, "mcp"))} with polite-crawler and {usd(cheapest(sonnet, "webfetch"))} with WebFetch. On the shortest page, {shortest.page}, a session cost {usd(claimCost(shortest, "sonnet", "mcp"))} with polite-crawler and {usd(claimCost(shortest, "sonnet", "webfetch"))} with WebFetch.

## The two models

A session with Opus costs approximately two times as much as a session with Sonnet, in each arm. The median session of polite-crawler costs {times(O.mcp.medianCostUsd, S.mcp.medianCostUsd)} times as much with Opus, and the median session of WebFetch {times(O.webfetch.medianCostUsd, S.webfetch.medianCostUsd)} times. ## The method

1. **The sessions.** In CI, a job for each arm starts the sessions one after the other. Each session starts in a new empty folder, with no settings and no `CLAUDE.md`. The workflow pins the versions of Claude Code and polite-crawler-mcp.
2. **The prompt.** The prompt gives the URL and the question. It asks for the exact words of the page between `<quote>` and `</quote>`.
3. **The usage.** The record of a session takes the tokens and the cost from the result of Claude Code. The record counts each model, also the small model of WebFetch.
4. **The checks.** The check of the claim compares the quote of the answer with the quote of the claim. For the check of the page, the summary fetches each page one time with the crawler. It looks for each quote of each answer on the page, word for word. It also accepts a quote with no inline Markdown.
5. **The repeats.** With Sonnet, each claim got {sonnet.repeat} sessions in each arm. With Opus, it got {opus.repeat} session in each arm.
6. **The stops.** `--max-turns` stops a session after 12 turns, and `--max-budget-usd` stops a session at 1 USD.

The <a href={readme}>README of the eval</a> gives each step. The code of commit <code>{evalB.commit}</code> made the summaries again, in <a href={runUrl(sonnet.summary)}>workflow {sonnet.summary}</a> and <a href={runUrl(opus.summary)}>workflow {opus.summary}</a>. The numbers of this page are in <a href={dataFile}><code>eval-b.json</code></a>.

## The limits

- **One run on one day.** The eval started each session one time, on {day}. The pages, the models and Claude Code change, so a different day can give different numbers.
- **Opus has only one session for each claim.** Sonnet has {sonnet.repeat} sessions for each claim in each arm.
- **The claims are short single facts.** Each session proves one fact on one page. Thus each claim pays the fixed cost of the MCP server one time. Part A counts that cost one time for a session of {count} claims.
- **The prompt gives the URL.** The agent does not search for the page.
- **The small model of WebFetch does the reading.** The main model sees only the answer of that small model. The eval checks the answer against the page, but the agent cannot.
- **Claude Code is in the two arms.** Its own system prompt is in each session of each arm, so it adds to the cost of the two arms. A different agent gives different costs.
