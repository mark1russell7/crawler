[Part A](../tokens-per-claim/) of the eval counted the tokens that an agent reads to prove {count} claims with exact quotes. It used a proxy tokenizer and no model. Part B asks the same questions in real sessions of Claude Code (`claude -p`), in CI. The tokens and the cost come from the usage that Claude Code reports, with each model of the session.

Each run gives each claim the same prompt in each of its arms, with the same model. The arms are:

- **`mcp`**: only the MCP tools of polite-crawler-mcp, with a new store.
- **`mcp-quote`**: the same server with `--tools quote`. The session gets only `crawl_fetch`, `crawl_find`, `crawl_read` and `crawl_verify`. Only the run of {second.mcp} has this arm.
- **`webfetch`**: only the built-in tool WebFetch.

The results:

- **WebFetch costs less than polite-crawler, also with the shorter tool text of {second.mcp}.** With Sonnet, the median session costs {usd(W.medianCostUsd)} with WebFetch. With polite-crawler, it costs {usd(S.mcp.medianCostUsd)} with {first.mcp}, {usd(L.medianCostUsd)} with {second.mcp} and {usd(Q.medianCostUsd)} with `--tools quote`.
- **The shorter tool text cut the tokens more than the cost.** With polite-crawler-mcp {second.mcp}, the median session read {cut(S.mcp.medianReadTokens, L.medianReadTokens)}% fewer tokens, and {cut(S.mcp.medianReadTokens, Q.medianReadTokens)}% fewer with `--tools quote`. The new version cut the median cost of a session by {cut(S.mcp.medianCostUsd, L.medianCostUsd)}% and {cut(S.mcp.medianCostUsd, Q.medianCostUsd)}%. It cut the cost for each quote on the page by {cut(S.mcp.costPerOnPageUsd, L.costPerOnPageUsd)}% and {cut(S.mcp.costPerOnPageUsd, Q.costPerOnPageUsd)}%.
- **polite-crawler gives more quotes that are word for word on the page.** With Sonnet, {L.onPage} and {Q.onPage} of {L.sessions} sessions have each quote on the page with {second.mcp}, and {S.mcp.onPage} with {first.mcp}. WebFetch has {W.onPage} of {W.sessions}. With Opus, the two arms are almost equal: {O.mcp.onPage} of {O.mcp.sessions} against {O.webfetch.onPage} of {O.webfetch.sessions}.
- **The writes to the cache make the difference.** A token that the main model writes to its cache costs 25 times a token that it reads from the cache. The tools of polite-crawler put text of the page into the context of the main model. The main model writes that text to its cache. WebFetch gives the page to a small model (<code>{evalB.helper}</code>), and the main model gets only a short answer.
- **Only polite-crawler lets the agent check its quote.** `crawl_verify` finds the quote in the stored page, and the stored capture has an id that a citation can name. With WebFetch, the main model does not see the page, so it cannot check the quote.
- **The WebFetch arm started one time.** The run of {second.mcp} changed only polite-crawler-mcp, so it did not start WebFetch again. For WebFetch, this page uses the sessions of the run of {first.mcp} with Sonnet.
- **The whole eval cost {usd(evalB.costUsd)}** for {allSessions} sessions, with a dry run for each version: {drySessions} sessions in total. The run of {second.mcp} cost {usd(lean.costUsd)}, and its dry run {usd(second.dryRun.costUsd)}.

### Two checks of an answer

- **The quote of the claim** (`verified`): the answer holds the quote of the claim.
- **Quotes on the page**: each quote of the answer is on the page, word for word.

The two checks give different counts. An answer can quote a different sentence of the page. Then its quote is on the page, but it is not the quote of the claim. For the question "What does the map method of an array return?", the two arms quoted "A new array with each element being the result of the callback function." That sentence is on the page and answers the question, but the claim has a different sentence.

By the check of the claim, WebFetch has a few more. With Sonnet, it has {W.verified}, against {S.mcp.verified} with {first.mcp} and {L.verified} with {second.mcp}. With Opus, it has {O.webfetch.verified} against {O.mcp.verified}.

With Sonnet, most quotes of WebFetch that are not on the page join or drop text. Examples are a footnote mark "[1]" in the quote, the pronunciation left out of "Alan Mathison Turing (23 June 1912 – 7 June 1954)", and two sentences joined as one. The small model of WebFetch reads the page, and the main model gets only its answer.

The sessions of polite-crawler with no quote on the page are almost all on one claim: the status code 418 of RFC 9110. That quote is past the cut of the reader, at 50,000 characters. With {first.mcp}, one session gave a quote that is not on the page. Two sessions, one with each model, stopped at the limit of turns with no answer.

With {second.mcp}, the description of `crawl_read` tells the model where the text stops, and that `crawl_verify` finds a quote past that point. On the claim of the status code 418, 4 of the 6 sessions of {second.mcp} said that the stored text stops before the section. They gave no quote. One session stopped at the limit of turns.

In one session, `crawl_verify` found a different sentence of the section. That quote is on the page, but it is not the quote of the claim. With {second.mcp}, one other session gave a quote that is not on the page, on WCAG 2.1.

These numbers show four facts:

- **The shorter tool text cut the cheapest kind of token.** The tool definitions are the same in each session. Thus the main model reads them from the cache, at the lowest price. With {second.mcp}, the median session of the arm `mcp` reads {tokens(readSaving)} fewer tokens from the cache than with {first.mcp}. At the price of a read, that is {usd(readSaving * evalB.prices[sonnet.model].cacheRead / 1e6)} for each session.
- **The writes to the cache are the largest part of the cost.** They are {share(Q.mainKindsUsd.cacheWrite, Q.costUsd)}% of the cost of the arm `mcp-quote`, and {share(L.mainKindsUsd.cacheWrite, L.costUsd)}% of the arm `mcp`. The median session writes {tokens(Q.mainTokens.cacheWrite)} tokens with `--tools quote`. The main model of WebFetch writes {tokens(W.mainTokens.cacheWrite)}.
- **WebFetch keeps the page out of the context of the main model.** The small model reads a median of {tokens(W.helperTokens.input)} tokens in each session, at {helperPrice("input")} for one million. That is the price of a read from the cache of Sonnet. The main model gets only the answer of the small model.
- **The writes to the cache cost more than the whole difference.** For {Q.sessions} sessions, the arm `mcp-quote` cost {usd(gap)} more than WebFetch. Its writes to the cache cost {usd(writeGap)} more. The small model of WebFetch cost {usd(W.helperUsd)}, and the arms of polite-crawler have no such cost.

The streams of the sessions show where the writes are. These numbers are medians from the artifacts `sessions-mcp`, `sessions-mcp-quote` and `sessions-webfetch` of the runs. `eval-b.json` does not hold them.

- **The first request of a session reads the text that the sessions of an arm share.** That text holds the tool definitions, so the shorter tool text of {second.mcp} is easy to see there. The first request writes a little more with polite-crawler than with WebFetch.
- **The later requests write the new part of the context.** That part holds the tool results and the turns of the model. The tool results of polite-crawler hold text of the page. The result of WebFetch is the short answer of the small model.

Thus the shorter tool text made a cheap part of the session smaller. The expensive part is the new text in the context of the main model. With polite-crawler, the later requests write 2,066 to 2,270 more tokens to the cache than with WebFetch. With WebFetch, the text of the page goes to the small model, and it does not come into that context.

The fixed part of the cost is large. ## The two models

A session with Opus costs approximately two times as much as a session with Sonnet, in each arm. The median session of polite-crawler costs {times(O.mcp.medianCostUsd, S.mcp.medianCostUsd)} times as much with Opus, and the median session of WebFetch {times(O.webfetch.medianCostUsd, W.medianCostUsd)} times. The ratio between the arms stays almost the same: with {first.mcp}, WebFetch costs approximately half.

With Opus, each claim has only one session in each arm. Thus with Opus, the cost of one claim can change more when the eval starts again. The eval did not start Opus with {second.mcp}.

## The method

1. **The sessions.** In CI, a job for each arm starts the sessions one after the other. Each session starts in a new empty folder, with no settings and no `CLAUDE.md`. The workflow pins the versions of Claude Code and polite-crawler-mcp.
2. **The prompt.** The prompt gives the URL and the question. It asks for the exact words of the page between `<quote>` and `</quote>`.
3. **The usage.** The record of a session takes the tokens and the cost from the result of Claude Code. The record counts each model, also the small model of WebFetch.
4. **The checks.** The check of the claim compares the quote of the answer with the quote of the claim. For the check of the page, the summary fetches each page one time with the crawler. It looks for each quote of each answer on the page, word for word. It also accepts a quote with no inline Markdown.
5. **The repeats.** With Sonnet, each claim got {sonnet.repeat} sessions in each arm of each run. With Opus, it got {opus.repeat} session in each arm.
6. **The stops.** `--max-turns` stops a session after 12 turns, and `--max-budget-usd` stops a session at 1 USD.
7. **The second run.** The run of {second.mcp} started only the arms `mcp` and `mcp-quote`, with the same claims, prompt, model and Claude Code. <a href={leanPr}>Pull request 38</a> made the tool text shorter. Part A counts these tokens with a proxy tokenizer. In that count, the text that the API gets on each turn went from 3,351 tokens to 2,372. With `--tools quote`, it went to 1,039.

The <a href={readme}>README of the eval</a> gives each step. The code of commit <code>{first.commit}</code> made the summaries of {first.mcp} again, in <a href={runUrl(sonnet.summary)}>workflow {sonnet.summary}</a> and <a href={runUrl(opus.summary)}>workflow {opus.summary}</a>. The run of {second.mcp} made its own summary, with the code of commit <code>{second.commit}</code>. The numbers of this page are in <a href={dataFile}><code>eval-b.json</code></a>.

## The limits

- **The eval started each arm one time.** The runs started on {day}. The pages, the models and Claude Code change, so a different day can give different numbers.
- **The eval did not start the WebFetch arm again.** For {second.mcp}, the comparison with WebFetch uses the sessions of the run of {first.mcp}. The two runs used the same model, Claude Code and claims, on the same day, approximately three hours apart.
- **Opus has only one session for each claim, and only with {first.mcp}.** Sonnet has {sonnet.repeat} sessions for each claim in each arm.
- **The claims are short single facts.** Each session proves one fact on one page. Thus each claim pays the fixed cost of the MCP server one time. Part A counts that cost one time for a session of {count} claims.
- **The prompt gives the URL.** The agent does not search for the page.
- **The small model of WebFetch does the reading.** The main model sees only the answer of that small model. The eval checks the answer against the page, but the agent cannot.
- **Claude Code is in each arm.** Its own system prompt is in each session of each arm, so it adds to the cost of each arm. A different agent gives different costs.
- **The split by the kind of token is a count, not a test of a cause.** The eval did not start sessions with a different read window or with smaller search results.
