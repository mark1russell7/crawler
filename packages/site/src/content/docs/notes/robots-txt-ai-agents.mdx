## The refusals for each agent

A site can refuse an agent in two ways. It can write a group for the agent, for example `User-agent: GPTBot` with `Disallow: /`. It can also refuse all bots with the group `*`. Then each agent without a group of its own gets that refusal.

<RefusalChart client:visible rows={rows} answered={s.answered} files={s.withFile} />

The training crawlers get the most refusals. {s.refusesAllTraining} sites refuse all seven of them. `Google-Extended` and `Applebot-Extended` are not crawlers: they are tokens. Googlebot and Applebot fetch the pages, and a group for the token tells Google or Apple not to use the pages to train its models.

The crawlers for AI search get fewer refusals than the training crawlers. A site that refuses a search crawler goes out of the answers of that search.

`PoliteCrawler` is a crawler that no site names. It thus gets the rules of the group `*`: {row("PoliteCrawler").refused} sites ({row("PoliteCrawler").share}%) refuse all bots that they do not name.

## One company, three agents

OpenAI and Anthropic each have three agents. One crawler collects training data, and one crawler collects pages for search. The third agent fetches a page when a person asks for it. Perplexity has a search crawler and an agent for a person.

<CompanyChart client:visible companies={companies(study)} />

For each company, the sites refuse the agent for a person less than the training crawler. {s.trainingNotUser.OpenAI} sites refuse GPTBot and let ChatGPT-User in. {s.trainingNotUser.Anthropic} sites refuse ClaudeBot and let Claude-User in. These sites refuse the use of their pages for training, but they let an assistant read a page for a person.

The MCP server of polite-crawler obeys the rules for `Claude-User` when it fetches a page for an assistant. [Read how](../../guide/mcp/). To write such rules for your own site, [use the recipe](../../block-ai-training-crawlers/).

## What the 1,000 domains answered

The Tranco list ranks domains, not websites. Many of the top domains serve a content delivery network, the DNS or an API, and have no website. {s.dns} of the domains have no address in the DNS.

<AnswerChart client:visible summary={s} />

The study puts each answer into one of four states:

- **A robots.txt file** ({s.withFile} sites). The verdicts come from the rules of the file.
- **No file** ({s.noFile} sites). These sites gave a 404 or a 410. They state no rules, so each agent is permitted.
- **Blocked at the edge** ({s.blocked} sites). The server answered with a refusal, a challenge or an error in place of the file. {blocked403} sites gave a 403, and {s.challenges} gave a challenge, for example a CAPTCHA page. The other sites gave a different 4xx, a 429 or a 5xx.
- **Unreachable** ({s.unreachable} domains). The crawler got no file that it could read. {s.dns} domains have no address in the DNS. In place of the file, {s.html} sites gave an HTML page (a home page or a sign-in page), so the crawler fetches nothing there. The other domains gave a TLS error, a timeout or a closed connection. {s.redirects} sent more than 5 redirects, and {s.undecodable} sent a body that the crawler could not decode.

The shares on this page count the files and the sites with no file: {s.answered} sites. They do not count the blocked or the unreachable domains.

### A 4xx and a block are two different questions

RFC 9309 tells a crawler what to do when it cannot read robots.txt. A 4xx means that the file is not available, so a crawler can fetch each path. A 5xx or no answer means that the site is unreachable, so a crawler fetches nothing.

This study asks a different question: what does a site tell each AI agent? A 403 to the request of the study does not answer that question. The edge of the site refused one request before it gave the file, so the rules for GPTBot stay unknown. Thus the study counts only a 404 and a 410 as "no file". It counts each other 4xx as a block, not as a site that permits each agent.

The crawler itself also stops at a 403. After a 403 or a 401, it sends no more requests to the site for 1 hour, and after a challenge for 24 hours. The stop stays when the crawler starts again.

## Content signals

A robots.txt file can also tell how the site permits the use of its content. Cloudflare published the `Content-Signal` line in September 2025, for example `Content-Signal: search=yes, ai-train=no`. Only {s.signals} of the {s.answered} sites write it:

| Signal | yes | no | Different in two groups |
| --- | --- | --- | --- |
| `search`: show the site in search results | {s.signalValues[0].yes} | {s.signalValues[0].no} | {s.signalValues[0].mixed} |
| `ai-input`: use the pages as input to an AI answer | {s.signalValues[1].yes} | {s.signalValues[1].no} | {s.signalValues[1].mixed} |
| `ai-train`: use the pages to train a model | {s.signalValues[2].yes} | {s.signalValues[2].no} | {s.signalValues[2].mixed} |

When a page refuses AI input, polite-crawler keeps the page but holds back its text from the AI reader. [Test a robots.txt with signals](../../tools/robots-txt-tester/).

## The method

1. **The list.** The study used the top 1,000 domains of the Tranco list <code>{study.list.id}</code>, from {study.list.date}. Tranco makes the list from the ranks of five sources across 30 days.
2. **The requests.** The crawler sent one request for `https://<domain>/robots.txt` to each domain, and followed a maximum of 5 redirects. It did not try again, and it did not try `www.<domain>`. All requests went out from one computer{study.runner !== undefined ? ` (${study.runner})` : ""} on {day}, with a new, empty store.
3. **The User-Agent.** Each request sent <code>{study.userAgent}</code>, with no contact. The address in it goes to [the page for site owners](../../bot/).
4. **The verdicts.** The function `decide` of polite-crawler decided each agent alone, as RFC 9309 specifies. The path was <code>{study.pagePath}</code>, a page path that no site names. Thus a refusal of this path is a refusal of the pages of the site.
5. **Redirects.** RFC 9309 lets a crawler read more than 5 redirects as "no file". The study, as the crawler, reads them as unreachable.
6. **One file for two domains.** Two domains can redirect to the same file. The crawler then asks for the file a second time with its `ETag`, and the server can answer `304 Not Modified`. The study uses the stored copy of the file, as the crawler does.

## The limits

- **Edge blocking.** A block can depend on the details of the request, for example the TLS connection of the client, and not only on the User-Agent. A different client can get the file. Some unreachable domains closed the connection, and this can also be a block.
- **One User-Agent.** Some sites give a different robots.txt to a different User-Agent. The study sent only the User-Agent of polite-crawler, not the User-Agent of each agent.
- **One try.** The crawler sent one request to each domain and did not try again. A timeout or a closed connection on that day puts a domain in "Unreachable".
- **Content signals.** A file can write a different `Content-Signal` line for each group. The table counts such a site in "Different in two groups", not by its first line.
- **Domains, not websites.** The list includes domains for content delivery networks, APIs and the DNS. Such a domain with no file counts as a site that states no rules.
- **A snapshot.** A site can change its robots.txt at any time, and some sites give a different file to different countries.
- **The network of the monthly runs.** The monthly runs send the requests from a GitHub Actions runner in a data center. Some sites block a data center more often than a home connection. Thus a change in the blocked sites can come from the network, not from the sites.
- **A request only.** A robots.txt does not stop a crawler that ignores it.
